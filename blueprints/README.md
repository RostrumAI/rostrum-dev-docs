# High-level implementation blueprints

A blueprint explains what we need to build technically to deliver an Epic. It describes the current capability and gap, major responsibilities, how the parts interact, why the approach fits, and the boundary between current work and future possibilities.

Use the [high-level implementation guide](../high-level-implementation-guide.md) for the format, examples, and self-review criteria. The [delivery methodology](../epic-delivery-methodology.md) defines the review required before a blueprint becomes the basis for a technical design.

## Adding a blueprint

Create a descriptively named workstream document in this directory. Link its parent Epic, identify its scope and owner, and add links to its [technical designs](../designs/README.md) as those are created. Link the blueprint from its Epic and list it here. A blueprint is not a file-by-file implementation plan.
